# Implementation spec — match-state scaffolding for rotating players

Authored by the internal Opus design gate, 2026-08-10 (~20:50 BST), in
response to the live game-6 deploy exposing pairing-state bleed (fresh
GEMINI seat opening onto game-5's 170-line chat.log, "SERIES 5-0 CODEX"
banner, and a KIMI/CODEX results ledger). Builder: fresh codex instance.
Verbatim spec follows.

**Goal:** `arcade start` produces a clean room for a new pairing. Social/broadcast state (chat, banner, logs) is per-match and reset; the series ledger persists but is always *read through a pairing filter*. No reset path may destroy unarchived state without snapshotting first (design-history §10).

Add to `main.py`, above `ARCHIVE_FILES`:

# PER-MATCH: belongs to one game; `arcade start` snapshots then clears it.
PER_MATCH_TRUNCATE = ["chat.log", "banner.txt", "eval.log", "keeper.log", "ctl"]
PER_MATCH_UNLINK = ["pending.txt", "result.txt", "draw_offer.txt", "TAMPER.txt", "roles.txt"]
PER_MATCH_GLOBS = [".stalls_*", ".last_*", ".prompt_out", ".ref_err", ".illegal"]

#   names.txt seats.txt roles.txt series.txt banner.txt
# Regenerated by ref init: moves.txt fen.txt board.txt

#   panes.txt .chatpane .dotspane .classicpane .newpane .panelpanes backup/

Per-file decisions:

- **chat.log** — per-match, truncate to empty then seed (§4). This is the reported bug.
- **banner.txt** — per-match, replaced with the seeded caption (§4). Never carried forward: the stale `SERIES 5-0 CODEX` line is exactly the wrong-pairing display.
- **results.txt** — series-scoped, **append-only, never truncated, never filtered on disk**. All filtering happens at read time.
- **eval.log / keeper.log** — per-match, truncate to empty. Both are single-game artifacts (eval.log is the host-only channel from the game-5 retro; keeper.log is the stall-nudge trace).
- **board.txt** — no action. `ref.py init` → `render()` rewrites it unconditionally; truncating it after init would blank the fresh board.
- **mode.txt** — untouched. Viewer display mode is an operator preference, not match state.
- **ctl** — per-match, truncate to empty. It is the TUI command channel; a stale command left in it can be re-read by the next viewer.
- **panes.txt** and the `.<name>pane` dotfiles — untouched. herdr pane topology is infra, outlives matches.
- **`__pycache__/`, `*.png`, `*.mov`, `crop_test.png`, `endgame*.mov`, `backup/`** — **explicitly out of scope tonight.** Backlog: an `arcade tidy` subcommand. `backup/` in particular must never be auto-pruned; it is the §10 safety net.
- **`engine/results.seed.txt`** — flag: contains two hardcoded `CODEX`/`KIMI` lines and is in no deploy list. Leave alone tonight, but do **not** start deploying it; delete or move under `docs/` in a follow-up.

## 2. Snapshot (widen the existing one)

Rename `snapshot_pre_init` → `snapshot_pre_start` and widen its input set. Same `<live>/backup/` destination, same `match-NNN`/epoch tagging.

```python
SNAPSHOT_FILES = ["moves.txt", "fen.txt", "chat.log", "banner.txt", "results.txt",
                  "names.txt", "seats.txt", "eval.log", "keeper.log", "result.txt"]

def snapshot_pre_start(live, newest):
    """Copy every non-empty file `start` is about to overwrite or clear into
    <live>/backup/<name>.<tag>.<ext>. Returns the backup dir, or None if
    there was nothing to save."""
```

Behavior changes from today:
- The gate is **per file**, not "moves.txt is non-empty". Today a finished match with an empty `moves.txt` but a 170-line `chat.log` snapshots nothing; that must not remain true once we truncate.
- Tag: unchanged — `match-{newest['match']:03d}` when a newest match exists, else `str(int(time.time()))`.
- Skips missing and whitespace-only files. Snapshot failure is fatal (`sys.exit(1)` naming the path) — refusing to start beats clearing without a copy.

## 3. Reset mechanics and ordering in `cmd_start`

```python
def reset_room(live):
    """Clear per-match social/broadcast/runtime state. Call ONLY after a
    successful ref init and only after snapshot_pre_start has run."""
    for fn in PER_MATCH_TRUNCATE:
        p = live / fn
        if p.exists():
            p.write_text("")          # truncate, never unlink: TUIs hold these open
    for fn in PER_MATCH_UNLINK:
        (live / fn).unlink(missing_ok=True)
    for pat in PER_MATCH_GLOBS:
        for p in live.glob(pat):
            if p.is_file():
                p.unlink(missing_ok=True)
```

Truncate-vs-unlink is deliberate: `chat.log`, `banner.txt`, `eval.log`, `keeper.log`, `ctl` are tailed by running panes, so they are emptied in place. The ref-owned flag files are unlinked because their *existence* is the signal.

**Exact `cmd_start` ordering** (steps 1–5 are today's code, unchanged):

1. Resolve root/live/games_dir; live-dir-override note; `ARCADE_ROOT` scratch-guard refusal.
2. `games_dir.mkdir`.
3. Newest-match-still-`live` refusal unless `--force`; `force_init = True`.
4. `next_match_number` → `match_dir.mkdir` (FileExistsError → error exit).
5. `live.mkdir`; deploy `GAME_DEPLOY_FILES[game]`.
6. **NEW** — build and validate `seats` (§6). Do this *before* any mutation so a bad seat name fails with nothing touched. Move the current `seats = {...}` construction up to here.
7. **NEW** — unarchived-match warning (§3a).
8. **WIDENED** — `backup_dir = snapshot_pre_start(live, newest)`.
9. Write `names.txt`, `seats.txt`, and **NEW** `roles.txt` (§4). These must precede init because `render()` reads `names.txt` (after the §7 fix).
10. `run_ref_init(...)`. On `CalledProcessError`: `rmtree(match_dir)` and exit — **no room state has been cleared yet**, so a failed start is recoverable.
11. **NEW** — `reset_room(live)` unless `args.keep_room`.
12. **NEW** — write `series.txt` and seeded `banner.txt`; seed `chat.log` (§4).
13. `write_match_json`; `print_runbook(data, live, backup_dir)`.

Note the ordering constraint that forces steps 9–11 apart: `render()` needs `names.txt` before init, but the room clear must come after init so a failed init destroys nothing. Identity files being overwritten by a failed start is acceptable — they are in `SNAPSHOT_FILES`.

### 3a. Is archive the invariant that makes truncation safe?

**No — the snapshot is.** Archive is not required and must not be enforced tonight (an operator who forgets it should still be able to seat game 6). The safety chain is: snapshot always runs, unconditionally, before anything is cleared, into `<live>/backup/`, which is never auto-pruned.

Archive is still what makes the match dir complete, so `cmd_start` warns when it was skipped. After step 5, when `newest` exists:

```python
if newest and not (newest[0] / "chat.log").exists() and (live / "chat.log").exists():
    print(f"note: {newest[0].name} was never archived (no chat.log in its match dir). "
          f"The live room is being reset for the new match; its contents are "
          f"snapshotted to {live}/backup/. Run `arcade archive` first next time.",
          file=sys.stderr)
```

Warning, not refusal. `--force` semantics unchanged and stay narrow: it overrides **only** the "newest match is still `live`" refusal. It does not enable, skip, or widen the reset — the reset always snapshots, force or not. So a `--force` start over a still-live match preserves that game's chat/board/logs in `backup/` before clearing.

Escape hatch: `--keep-room` on `arcade start` skips step 11 entirely (identity files and `series.txt`/`banner.txt` are still rewritten). For re-seating an interrupted match or dev iteration. It does not skip the snapshot.

## 4. Fresh-room seeding

**Reserved system author: `ARCADE`.** All-caps, matching the existing `REFEREE`/`DIRECTOR`/`HOST` convention. It is the CLI's voice, distinct from the host agent's.

`roles.txt` (new, written at step 9) removes the stale-role leak — `chat.roles()` overrides `role_of` and a leftover `kimi white` line would misclassify a departed player:

```
GEMINI white
CODEX black
ARCADE facilitator
REFEREE facilitator
DIRECTOR facilitator
HOST facilitator
```

(`chat.roles()` lowercases keys on read, so casing here is cosmetic.) Also add `'arcade'` to `chat.FACILITATOR_HINTS` so classification survives a missing `roles.txt`.

`chat.log` seed (step 12) — one line, written directly rather than via `chat.say` (the CLI does not import engine modules):

```python
line = (f"match-{num:03d} opens: {W} ({c1.title()}) vs {B} ({c2.title()}). "
        f"Fresh room — the previous match's chat is archived. "
        f"Series, this pairing: {series_short}.")
(live / "chat.log").write_text(f"{int(time.time())}\tARCADE\t{line}\n")
```

Single-line and printable — it passes through `chat.clean()` on read, so keep it plain (an em dash is fine; `clean` only strips non-printables and collapses whitespace).

`banner.txt` seed:

```
GAME 6 — GEMINI vs CODEX — FIRST MEETING
```
or, with history, `GAME 7 — GEMINI vs CODEX — GEMINI 1-0 CODEX`. One line, under ~80 chars; it renders as the board caption in `tui_dots.py`/`tui_xiangqi.py`.

`series.txt` (new file, the backlog item from `seat-feedback-game5.md`) — exactly one line, the current pairing's head-to-head:

```
GEMINI 0-0 CODEX (0 games)
```

## 5. Series semantics with rotating players

`results.txt` stays append-only and cumulative; names are in every line, so it is the storage and the *filter* is the display contract. Add to `main.py`:

```python
VALID_SCORES = ("1-0", "0-1", "1/2-1/2")

def parse_results(text):
    """[(white, score, black)] from `<WHITE> <SCORE> <BLACK>` lines; skips junk."""
    rows = []
    for ln in text.splitlines():
        p = ln.split()
        if len(p) == 3 and p[1] in VALID_SCORES:
            rows.append((p[0].upper(), p[1], p[2].upper()))
    return rows

def head_to_head(rows, a, b):
    """(wins_a, wins_b, draws, games) for the {a,b} pairing, order-insensitive:
    a line counts whichever colour each player held."""
    a, b = a.upper(), b.upper()
    wa = wb = dr = 0
    for white, score, black in rows:
        if {white, black} != {a, b}:
            continue
        if score == "1/2-1/2":
            dr += 1
        elif (score == "1-0") == (white == a):
            wa += 1
        else:
            wb += 1
    return wa, wb, dr, wa + wb + dr

def series_short(a, b, rec):
    wa, wb, dr, n = rec
    if not n:
        return "FIRST MEETING"
    tail = f", {dr} draw(s)" if dr else ""
    return f"{a} {wa}-{wb} {b} ({n} game(s){tail})"
```

**Every series display is pairing-filtered.** Concretely:

- `series.txt` / seeded `banner.txt` / seeded chat line — `series_short(W, B, head_to_head(parse_results(...), W, B))`.
- **`cmd_status`** — replace the current `series: {last line}` (which prints the previous pairing's last result verbatim) with:
  ```
  series (GEMINI vs CODEX): FIRST MEETING   [results.txt: 5 line(s) total]
  ```
  Pairing comes from the resolved match's `match.json` seats, falling back to `names.txt` when no match.json is found. With neither, print `series: (no pairing known)`.
- **`cmd_results`** — keep the per-match listing and the all-time tally, and insert a per-pairing block. It reads `match.json`, not `results.txt`, so grouping is by `frozenset({white, black})`:
  ```
  == chess ==
    match-001  CODEX vs KIMI  [complete]  CODEX 1-0 KIMI
    ...
    match-006  GEMINI vs CODEX  [live]  (pending)
    head-to-head:
      CODEX vs KIMI:    CODEX 5-0 KIMI (5 game(s))
      CODEX vs GEMINI:  FIRST MEETING (1 pending)
    all-time: CODEX 5  KIMI 0  GEMINI 0   1 pending/undecided
  ```
  Sort pairing blocks by games played descending, then alphabetically, for stable output.
- **`--pairing`**: add `r.add_argument("--pairing", nargs=2, metavar=("A", "B"))`. When given, restrict both the match listing and the head-to-head block to that pairing (order-insensitive, case-insensitive) and suppress the all-time line. **Per-pairing grouping is the default**; the flag is only a filter. Rationale: with rotating players an ungrouped "series" number is meaningless, so grouping cannot be opt-in.

## 6. Seat-name validation (new, at step 6)

Two cheap refusals this scaffolding now depends on:

```python
RESERVED_NAMES = {"ARCADE", "REFEREE", "DIRECTOR", "HOST", "WHITE", "BLACK"}
```

- Refuse if `seats["white"]["name"] == seats["black"]["name"]` — identical names make `seats.txt`, `roles.txt`, `role_of()` and `head_to_head()` all ambiguous.
- Refuse if either name is in `RESERVED_NAMES` — a player named `HOST` would be classified `facilitator` by `roles.txt` and could not be seat-checked.

Both exit(1) naming the offending value and the reason. Existing whitespace/`human:` validation in `seat()` is unchanged.

## 10. Edge cases to handle explicitly

- **Live dir does not exist yet** — `reset_room` and `snapshot_pre_start` are no-ops; seeding creates `chat.log`/`banner.txt`/`series.txt` fresh.
- **`results.txt` missing or malformed** — `parse_results` skips unparseable lines silently; a missing file yields `FIRST MEETING`. Never crash `start` on a bad ledger line.
- **Human seats** — `human:ada` → `ADA`; pairing filtering is purely name-based and works unchanged.
- **Case** — normalize to upper in `parse_results`/`head_to_head`; `seat()` already uppercases.
- **A player renamed between matches** — out of scope; head-to-head is name-identity, documented as such in `cli-brief.md`.
- **Running TUIs** — truncate-in-place (not unlink) for the tailed files; renderers already degrade on empty input.
- **Files held open by a dead keeper** — `unlink(missing_ok=True)` throughout; never raise on cleanup.
- **`ctl` cleared while a viewer polls it** — empty is the idle state, harmless.
- **Concurrent `arcade start`** — unchanged known gap, single-operator tool.
